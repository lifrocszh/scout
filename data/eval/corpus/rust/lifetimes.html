Lifetime annotations

What they describe

A lifetime annotation such as 'a does not change how long a reference lives. It tells the compiler how the lifetimes of several references in a function signature relate, so it can prove a returned reference never outlives the data it points to.

Elision

In common cases the compiler fills in lifetimes for you. With one input reference, the output reference gets the same lifetime. With a self parameter on a method, the output borrows from self.

Example

fn longest<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}
